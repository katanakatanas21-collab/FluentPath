## Architecture

- Frontend: React 19, React Router 6, and Create React App in `frontend/`. API requests use `frontend/src/auth.js` and the FastAPI service at `http://127.0.0.1:8000`.
- Backend: FastAPI/Pydantic in `backend/server.py`; records are persisted as JSON files under `backend/data/`. There is no production database integration.
- Authentication: email/password login returns a one-hour HS256 bearer token. Passwords are stored as salted hashes. The frontend stores the token in local storage and sends it on API requests. The backend resolves the current user from the token; logout revokes the token in the running process.

## Roles and product functionality

- Roles are `student`, `teacher`, and `administrator`; protected backend routes derive the role from the authenticated account. Teachers are scoped to their classes/courses, administrators have staff and moderation endpoints, and students access their own records.
- Students can register, take/save a trial test, see courses and lesson progress, submit assigned homework, view classes/schedule, and use community and messaging.
- Teachers can view assigned students/courses, create and grade homework, manage classes, and participate in community and related messaging.
- Administrators can view dashboard/user/course/class information, manage CEFR courses and lessons through the Content Studio, review community reports, moderate posts, and message teachers.
- Courses include CEFR courses and entries marked as future. CEFR availability is checked server-side against the student's recorded level. Future courses are presented without lesson access.
- Lesson completion is persisted on the student record in `courseProgress`; completion requires an available CEFR course and valid lesson.
- Gamification MVP data is persisted in each student's `gamification` object: XP, action deduplication keys, streak dates/counts, and earned badge IDs/timestamps. Levels are derived from configurable thresholds; XP rewards come only from trusted backend actions.
- Students earn XP for first lesson completion, first homework submission, first teacher grade, and first placement-test completion. Daily streaks, eight achievement badges, and an email-free student leaderboard are implemented. The dashboard and `/achievements` show XP, level progress, streaks, badges, and leaderboard preview.
- AI Teacher offers conversation, grammar, vocabulary, writing, and text-only speaking preparation. It gets CEFR from the authenticated student, validates structured provider output, retains owner-scoped messages in separate JSON stores, and limits provider requests to 20 per student per hour. Writing feedback has separate grammar, vocabulary, clarity, and relevance notes. One qualifying completion per mode per UTC day can earn a server-fixed 10 XP; model/frontend XP values are never trusted. The AI Teacher dashboard shortcut and bilingual practice/history UI are implemented.
- Homework supports teacher assignment by course, level, or selected students; students submit answers and teachers can grade with feedback.
- Classes support teacher ownership, assigned students, schedule fields, cancellation, manual meeting URLs, and Zoom Server-to-Server OAuth meeting create/update/start/cancel. `/api/teacher/meeting-options` reports only whether credentials are configured; `/api/teacher/classes/{class_id}/zoom-start` fetches a fresh teacher start URL after verifying class ownership. Student APIs return the participant link only, and the administrator class overview omits meeting URLs. Zoom host/start operations require backend environment settings; attendance is not recorded, so class attendance XP and the First Class badge are not yet awarded. Zoom webhooks and live-account verification are not implemented.
- Community supports general/course/class-scoped posts, replies, ownership edits/deletes, likes, reports, and moderation. Messaging supports class-related student/teacher conversations, administrator/teacher conversations, access-scoped threads, and read state.
- In-app notifications are persisted in `backend/data/notifications.json` and scoped to the authenticated identity. Homework assignment/submission/grading, messages, community replies/reports, new registrations, class cancellations, lesson/course progress, XP badge/level/streak milestones, and near-term class views generate deduplicated notifications. Class reminders are generated when relevant class lists are opened within 24 hours of start time. Notification list/bell and mark-read actions are available for students, teachers, and administrators.

## Notification persistence routing fixed and proven - 2026-10-03

- **The notification routing defect is fixed in product code.** `persistence/runtime.py` now resolves a path to a store without asking the backend, because a PostgreSQL backend has no file to ask about. `store_name_for_path` consults a process-wide path resolver installed by `configure`, and falls back to each store's canonical filename so routing can never depend on ambient resolver state.
- **`build_store` was made a pure constructor.** It previously installed its resolver globally, so any throwaway `build_store(..., path_resolver=lambda ...)` anywhere in the process silently repointed product store paths and reopened the fallback. Installing a store and its resolver is now `configure`'s job alone. This was found by the live suite, not by inspection, and is the reason the routing regression tests exist.
- **PostgreSQL mode now fails closed.** `server.py` resolves the store name first; an unresolved path raises `DataStoreError` (surfacing as `503 DATA_STORE_UNAVAILABLE`) instead of writing a file. The direct-file fallback is retained only in JSON mode, where a file **is** the store.
